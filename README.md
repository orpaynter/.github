# OrPaynter GitHub map

**Canonical vs historical.** Every repo stays, but not every repo is the product. This page is the index so another human or model does not treat an old template, fork, demo, or synthetic bundle as production truth.

Company GitHub face: [github.com/Orpaynter-Inc](https://github.com/Orpaynter-Inc).

Private / production-scoped foundations. These are the four repositories that matter for Wave 1.

| Repo | Role | Do not confuse with |
|---|---|---|
| [AIA](https://github.com/orpaynter/AIA) | Backend authority layer. FastAPI foundation, intelligence services, Decision Package logic, and human-gate controls. | Older `agsi_v2` folders, local dumps, or generic AI backends. |
| [claimflow](https://github.com/orpaynter/claimflow) | Shared claim operating flow: case state machine, Intake Foreman, TRAE/AIA gates, and portable proof. | Marketing copy, visual-only ClaimFlow pages, or old overlay sites. |
| [orpa](https://github.com/orpaynter/orpa) | Governed operator console. Identity-bound approve/reject, fail-closed posture, payments disabled. | Generic agent consoles or autonomous operators. |
| [orpaynter-web](https://github.com/orpaynter/orpaynter-web) | Public product and verification surface. ClaimFlow site, `/record`, `/arena`, synthetic proving ground. | `website`, Nexus spaces, starter sites, or unverifiable landing pages. |

## Operating law

1. The system drafts. A human approves.
2. Agents may become more capable. They may never give themselves more authority.
3. Every money-facing or customer-facing action needs a reconstructable Decision Package plus evidence.
4. Do not publish accuracy, ROI, customer counts, certifications, or production claims that cannot be shown on real jobs.
5. Synthetic proof is useful. It is not customer validation.

---

## What a visiting operator should do

1. Read this map first.
2. Start with AIA + claimflow + orpa + orpaynter-web if you have access.
3. Treat `/record`, `/arena`, synthetic bundles, and portable verification scripts as **synthetic / machine proof** until a real human verifies a real job.
4. Do not auto-approve.
5. Do not claim customer production from HTTP 200.
6. If files disagree: company identity wins on who we are; AIA + ClaimFlow win on what the product does; a real job plus tests win on what works; the newest PDF or demo never wins by default.
